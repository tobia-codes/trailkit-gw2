# trailkit-memo

- **Status:** draft — requirements settled (M1–M15)
- **Crate path:** `addons/trailkit-memo`
- **Nexus signature / ID:** TBD

## Goal

An in-game notes app: a tree of groups/subgroups with markdown notes, reset-
aware checklists (daily/weekly), and — with trailkit-core — live event
references with autocompletion and status.

## Requirements (from user)

### Notes & structure
- List of notes, edited as **markdown**.
- **Groups and nested subgroups**; notes live in groups.
- Notes, groups and subgroups have **stable unique IDs**.
- Notes and groups are **reorderable / movable by drag & drop**.
- Note **type**: normal (default), **daily reset**, **weekly reset**. On reset
  all checkboxes in that note are unchecked.
- Cancelling an edit with unsaved changes asks for confirmation.
- Keybind opens/closes the notes window.

### Events (requires trailkit-core)
- Typing `/e` in a note opens **autocompletion** of events.
- Event references show start time and whether the event is running now.
- Selected/referenced events are visible to trailkit-event (highlighting).
- Without core: event settings greyed out + hint "more features with
  trailkit-core"; memo works as a plain markdown notes list.

### Import / export / backup
- Export and import **lists** (notes/groups).
- Export and import **settings**.
- **Backup**: one file with settings + all notes.
- Import of notes that already exist (same ID) opens a dialog to choose which
  existing notes get updated.

### Project-wide
- Own settings window, help page, en/de, themes, performance (sleep when
  closed).
- Title bar `?` button, problem page and own log (ROADMAP R89, M179).

### Wishes from 2026-11-13 (not grilled yet)
- **Checked checkboxes strike through** the text after them.
- **A second, very simple window** next to the main window that shows, for
  example, the daily and weekly notes.
- **Favorite notes**: mark notes as favorites and filter by them.

## Technical design (proposal)

- IDs: UUID v7 (time-ordered) newtypes `NoteId`, `GroupId`.
- Storage: see M16–M18.
- Editor: Dear ImGui has no rich-text editor. Proposal: **edit mode** = raw
  markdown in a multiline input (with `/e` autocomplete via input callback);
  **view mode** = rendered markdown (headings, lists, bold/italic, links,
  checkboxes clickable, event chips). Renderer: M19.
- Event reference syntax: see M7.
- Reset times: daily 00:00 UTC, weekly Monday 07:30 UTC (GW2 standard
  resets). Reset applied on next open / on timer while running, based on
  `last_reset_applied_at` per note (so it also works if the game was closed).
- Export format: versioned JSON with `schema_version`.

## Open questions

- **Q501 – Toasts hard to see** (user feedback 2026-11-17, in-game test 21): the neutral toast ("Moved to the trash",
  `bg.popup` with `border.subtle`) barely stands out from the note pane in Dark. Recommendation: an R87 mockup with
  two or three variants (e.g. stronger border, the tooltip shadow, a lighter surface), Dark/Light, before any change.

*Answered yes on 2026-11-09: Q151, Q164, Q165, Q166 (amended), Q168 (amended), Q169, Q170, Q171; mockup V4 approved (R87). Kept here until M180 and R89 are implemented.*

- **Q151 – Dead storage worker.** Recommendation: the toast keeps "Erneut versuchen"; a click starts a new worker in
  "write only" mode (no reload, keeps the saving permissions) and writes the UI's current documents, once per click,
  only when the old thread has really ended (test), the panic stays logged with its cause.
- **Q164 – Close button.** Recommendation: the error toast has a Lucide `x` (tooltip "Schließen", `draw_icon_button`);
  closing only hides it, retries go on, it returns when the next change fails. The user saw it in the mockup and said
  "sieht gut aus"; not yet answered explicitly.
- **Q165 – Wording at minimum width.** The generic title does not fit one line at 320 px (toast max. 288 px). Either the
  toast wraps (component change) or the text is shortened to "Speichern fehlgeschlagen". Recommendation: shorten.
- **Q166 – Log format of save errors.** *Amended by Q219 (2026-11-09): `save_retry_manual` and `shutdown_save` are not logged; `file=` replaces `document=` (R92).* One line per event, `event` plus `key=value`: `save_failed document= attempt=
  stage= kind= os_error= bytes= unsaved_for=`, `save_recovered`, `save_gave_up`, `save_retry_manual`, `worker_died`,
  `worker_restarted`, `shutdown_save`. `document` is notes/drafts/settings/ui_state, `stage` write_temp/flush/rename/
  delete, `os_error` the raw Windows code (32 locked, 5 denied, 112 disk full). WARN per attempt, ERROR for giving
  up, INFO for recovery. Never note content or absolute paths; a test checks it. Recommendation: yes.
- **Q167 – Own log file.** *Settled by ROADMAP R92 (central `trailkit/logs/<addon>.log`, 30 days); the text below is history.* Each addon writes `trailkit-<addon>.log` in its own data folder through a shared crate
  (rule 7): one line per event, ISO 8601 time with the UTC offset, `addon=`, `version=`, then `event` and `key=value`
  fields (the save-error format, Q166); no content, no absolute paths; two files of 1 MiB at most; warnings and
  errors are also forwarded to `Nexus.log`. Recommendation: yes.
- **Q168 – Export button.** *Amended by R92 and settled by ROADMAP R95 (file name, 3 days, 5 MiB, format, status line).* The button writes one text file `trailkit-<addon>-log-<date>.txt` (header with addon,
  version, Nexus version, language, time zone, then the log) to the user's Downloads folder and opens Explorer with
  the file selected. Feedback is a line next to the button, not a toast. Recommendation: yes.
- **Q169 – Help window.** `?` opens the shared help window with the problem page first, then the addon's help pages
  (`help/{en,de}.md`). The Nexus options button "Open help" (R53) opens the same window; the window menu gets no
  second entry. Recommendation: yes.
- **Q170 – Problem link.** "Report a problem" opens the repository's GitHub issue form in the default browser with
  addon and version in the URL; nothing else is sent. Needs an issue form template in the repository and a line in
  `PRIVACY.md` (the link goes to GitHub, USA). Recommendation: yes.
- **Q171 – Placement.** `?` sits at the right end of the title bar, before the collapse chevron and the `x`.
  Visual proposal in Dark and Light, with tooltip, minimum width and German, before any implementation (R87).
